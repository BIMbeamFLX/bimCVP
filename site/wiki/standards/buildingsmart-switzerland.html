buildingSMART Switzerland

The Swiss implementation reference as an optional regional profile: Bauen digital Schweiz / buildingSMART Switzerland, KBOB, BIM-Abwicklungsmodell, national terminology and BIM2FM handover logic.

Regional profile

Switzerland is useful as a regional adapter because the Swiss references combine ISO 19650 terminology, national glossary work, public procurement guidance and operation-oriented BIM2FM practice.

Why Switzerland is useful

Switzerland is useful as a regional profile because it is multilingual, procurement-aware and lifecycle-oriented. It also sits between German, French and Italian terminology, which makes it a good example for local terminology and procurement adapters.

Reference stack

The Swiss stack is not a replacement for buildingSMART International. It is the national process layer on top of the international standards. 

buildingSMART International
  -> IFC, BCF, IDS, bSDD, openCDE

  -> ISO 19650, EN 17412, EN ISO 29481

  -> BIM-Abwicklungsmodell, National Glossary, Stufenplan, Expert Groups

KBOB
  -> public-client BIM recommendations

Gemeinwert / BIM-CVP
  -> signed event workflow and interoperable clients

BIM-Abwicklungsmodell

The BIM-Abwicklungsmodell explains information management in digital planning, construction and operation across the life cycle. For this wiki, its most useful contribution is structure: it separates organisation, project and asset/operator layers and links information requirements to use cases, information delivery and CDE workflow.

KBOB and public clients

KBOB is important because it frames BIM for public and institutional clients. For BIM-CVP, KBOB-style requirements translate into explicit contract annexes: open standards, structured data delivery, data ownership, security, liability and clear handover rules.

Procurement rule for this project: a CDE requirement should never say only "use platform X". It should require exportable IFC, BCF, IDS/openCDE workflows, auditability, role model and data handover.

National Glossary

The National Glossary matters more than it looks. If German, French and Italian teams use different words for the same role or state, the software must not silently collapse them. BIM-CVP should store stable internal codes and render national labels per language.

Internal codeSwiss/ISO-facing labelWhy code wins
appointing-partyClient / AuftraggeberseiteSame role can render differently by country.
lead-appointedLead appointed partyISO-compatible for international projects.
info-managerInformation manager / BIM manager contextCountry-specific title, stable permission group.
SharedShared / geteilt / condivisoState machine must not depend on UI language.

BIM2FM and AIM

BIM2FM is where the workflow stops being only planning coordination. The owner needs an Asset Information Model, data fields for operation, and a way to connect project information to facility management. In the event model this means BCF is only the first workflow; maintenance, product data, site diary, LCA and approvals are the next layers. 

PIM during design/construction
  -> IFC file references
  -> BCF topics
  -> IDS validation
  -> approval

handover
  -> AIM package
  -> operation data field catalogue
  -> maintenance cycles
  -> product data and evidence links
