gemeinwert / BIM + Nostr

BIM gives buildings a shared language. Nostr gives records a signature.

BIM-CVP maps existing openBIM work into signed Nostr events. IFC, BCF, IDS and ISO 19650 stay the domain standards. Nostr supplies portable identity, signatures, relays and a simple event log.

The split.

BIM is the building domain: models, issues, requirements, approvals and handover records. Nostr is the transport and signature layer: who created a record, when it was created, what it references and where the payload can be found.

This split is the core rule. We do not invent a new BIM schema. We sign and route the records that BIM tools already understand.

Standards fixed now.

Layer Standard Use in events
Model IFC 4.3.2.0, read support for IFC4 / IFC2x3 File reference, project GUID, element GUIDs, schema and authoring-tool tags.
Coordination BCF API 3.0 / BCF XML 3.0 Topics, viewpoints, comments, status changes and audit trail.
Requirements IDS 1.0 Machine-checkable delivery requirements attached to projects, models or packages.
Process ISO 19650, EN 17412-1 LOIN WIP / shared / published states, information need, responsibility and approval authority.
CDE bridge OpenCDE Foundation 1.1, Documents API 1.0 Adapter target for classical CDE platforms and document handover.
Use cases IDM / buildingSMART UCM Process references that explain why each information exchange is needed.

Version pinning matters. Event definitions only become testable when the BIM standard version behind each event is explicit.

Base tags every BIM event should understand.

d
Stable replaceable identifier, for example project id, topic id or requirement id.
a
Reference to parent project, model, topic or requirement event.
x
SHA-256 hash for file-backed payloads.
url
Download location for IFC, BCF, PDF, IDS or snapshot payloads.
ifc
Element reference inside an IFC model.
bcf-status
BCF topic state such as Open, InProgress, Resolved or Closed.
cde-state
ISO 19650 state: WIP, shared, published or archived.
